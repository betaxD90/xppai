# xppAI AX 2009

**Guidance for understanding and changing Microsoft Dynamics AX 2009 X++.**

## Pick the right generation first

| Your system | Package and scope |
| --- | --- |
| **Microsoft Dynamics AX 2009** | This package: legacy X++ analysis, support and posting investigations, change review, and XPO inspection. |
| **Microsoft Dynamics AX 2012 R3** | [xppai-ax2012](../packages/xppai-ax2012/README.md): R3 analysis, change guidance, project notes, and XPO tooling. |
| **Dynamics 365 Finance and Supply Chain Management (D365FO)** | [xppai-365](../packages/xppai-365/README.md): D365FO X++ and readable metadata, diffs, diagnostics, and requirements. |

Each generation has its own skills and CLI. Use the package that matches the system you are working on.

## What this AX 2009 package does

Bring a method, class, form, table, XPO, stack trace, profiler trace, or business support symptom. The assistant can explain unfamiliar code, trace posting and performance problems, review design and change risks, or propose a focused fix. The CLI can inventory and query objects from a local XPO cache.

The answer depends on the evidence you provide. Reading source can establish what that source says; it cannot confirm which customization runs in your AX environment or whether a proposed change compiles there.

## Meet `xppai-papai`

**Papai leads when the AX 2009 request is mixed or unclear.** Give it the artifact and your goal. It works out what matters, selects the smallest useful sequence of specialist skills, checks the evidence, and turns the findings into one practical answer. A support symptom might lead to `xppai-support`, then to `xppai-posting` or `xppai-explain` when code evidence arrives.

That is why Papai is a good first call for a messy problem: it connects the specialists and knows when to stop. For a narrow question, call a specialist directly. For a fixed, repeatable analysis of an artifact, use `xppai-babysit`.

> **Try it:** “Use `xppai-papai` to investigate this AX 2009 posting error. Here is the message and the relevant X++ method; explain the likely cause and the next check.”

## The AX 2009 crew

| Skill | What it does |
| --- | --- |
| `xppai-papai` | Leads mixed or unclear work and combines the right specialist findings. |
| `xppai-babysit` | Runs a predefined, structured analysis based on the artifact type. |
| `xppai-explain` | Explains unfamiliar methods, classes, forms, and tables. |
| `xppai-support` | Investigates business or support symptoms before the code path is known. |
| `xppai-stack` | Reads stack and profiler traces to investigate performance. |

| `xppai-architect` | Reviews responsibilities, coupling, and design boundaries. |
| `xppai-risk` | Assesses the impact of a proposed change. |
| `xppai-codefix` | Proposes a focused fix once the defect and context are understood. |

## Install and start

Node.js 18 or newer is required. From the repository root, install the AX 2009 skills for your assistant:

```powershell
node .\bin\xppai.js list
node .\bin\xppai.js install --target codex
```

You can also install this package globally from the checkout and use its shorter command:

```powershell
npm install -g .
xppai install --target codex
```

Other supported assistant targets and export options are in [Targets and installation](targets.md). The CLI installs guidance; it does not run AX or an AI model.

### Optional XPO command-line workflow

The CLI can load a local XPO into its cache and query its objects. Take a snapshot before cache-based queries:

```powershell
xppai xpo load "./path/to/export.xpo"
xppai xpo snapshot --json
xppai xpo list --type Class
xppai xpo read --type Class --name MyClass
xppai xpo grep --contains "search text"
```

If you did not install globally, use `node .\bin\xppai.js` in place of `xppai`. For ordinary skill analysis, the cache is optional: provide the XPO file directly when your assistant can read local files, or paste its contents.
